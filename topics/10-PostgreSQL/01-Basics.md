## Fundamentals

### Beginner

#### 1. What is PostgreSQL, and what are some features that distinguish it from other relational databases?

PostgreSQL is an open-source object-relational database system. It supports standard relational features such as tables, constraints, and transactions, along with extensible types, user-defined functions, extensions, JSON and JSONB, arrays, and range types. It emphasizes correctness and extensibility, but performance and operational behavior still depend on schema design and workload.

#### 2. What is the difference between a PostgreSQL database and a schema?

A database is a separately connectable container within a PostgreSQL cluster. A schema is a namespace inside a database that groups objects such as tables, views, and functions. Schemas help organize objects and manage name resolution and privileges; they are not separate databases or strong isolation boundaries.

#### 3. What is the difference between `SERIAL` and an identity column?

`SERIAL` is shorthand that creates an integer column, a sequence, and a default using that sequence. Identity columns use SQL-standard syntax, make the sequence dependency explicit, and support `GENERATED ALWAYS` or `GENERATED BY DEFAULT` behavior. For new designs, identity columns are generally clearer; neither choice by itself guarantees gap-free values.

#### 4. How do `PRIMARY KEY`, `UNIQUE`, and `NOT NULL` constraints differ?

A primary key uniquely identifies each row and implies both uniqueness and non-nullability. A unique constraint prevents duplicate key values, while its handling of nulls depends on the constraint definition and PostgreSQL version. `NOT NULL` independently prohibits null values. Constraints are enforced by the database, so they protect data regardless of which application writes it.

### Practical

#### 5. How do you insert a row and return its generated identifier in PostgreSQL?

Use `INSERT ... RETURNING` to get values from the inserted row without issuing a separate query:

```sql
INSERT INTO customers (email)
VALUES ('dev@example.com')
RETURNING id, created_at;
```

This also works with `UPDATE` and `DELETE`. It avoids a race-prone follow-up lookup and is convenient for application code.

#### 6. How does PostgreSQL handle an insert-or-update operation?

Use `INSERT ... ON CONFLICT` with a unique constraint or unique index that identifies the conflict:

```sql
INSERT INTO inventory (sku, quantity)
VALUES ('A-17', 5)
ON CONFLICT (sku)
DO UPDATE SET quantity = inventory.quantity + EXCLUDED.quantity
RETURNING quantity;
```

`EXCLUDED` refers to the proposed row. This operation is atomic for the conflict target; it does not remove the need to define correct constraints or handle other possible errors.

#### 7. How does PostgreSQL resolve an unqualified table name?

PostgreSQL searches schemas in the current session's `search_path` and uses the first matching object. The path can be inspected with `SHOW search_path`. Applications should avoid relying on an unsafe or surprising path, especially when users can create objects in searched schemas; qualifying important objects as `schema.table` makes resolution explicit.

### Advanced and Production

#### 8. Why can a sequence or identity-generated column contain gaps?

Sequence values are allocated independently from transaction commit. A transaction can consume a value and then roll back, and concurrent sessions can allocate values in an order different from commit order. Sequence caching and conflict-handling paths can also leave gaps. Sequences are suitable for unique identifiers, not invoice numbering that must be gap-free.

#### 9. When would you use a PostgreSQL extension, and how do you manage one safely?

Extensions add database capabilities, such as additional data types, indexes, or functions. First check that the extension is supported by the deployment environment, then install and version it through controlled migrations (for example, `CREATE EXTENSION`). Include extension versions in deployment planning and test upgrades and restores, since an extension may require server packages or elevated privileges.

#### 10. What is the difference between a role and a user in PostgreSQL?

PostgreSQL roles represent identities and permissions. A role with the `LOGIN` attribute can connect; a role without it can be used to group privileges or be assumed by another role. `CREATE USER` is effectively shorthand for creating a role with login enabled. Grant only the required privileges and avoid using a superuser account for application connections.
